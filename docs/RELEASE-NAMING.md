# 发布命名规范

适用范围：所有对外发布的安装包、构建制品、发布单与版本页文案。
唯一的版本号真源是仓库根 `VERSION`，构建号由 CI 运行号注入，两者都不带人名、日期或流水号后缀。

## 1. 产品名

| 端 | 产品名 | 说明 |
|---|---|---|
| iPhone | 黄杨科技 | 默认形态，不带任何后缀 |
| iPad | 黄杨科技 HD | `HD` 固定大写、与产品名之间一个空格，表示 iPad 专属布局 |

`HD` 只用于区分端，不用于区分版本、渠道或签名方式。

## 2. 文件命名公式

```
黄杨科技-<版本>-b<构建号>.ipa        # iPhone
黄杨科技-HD-<版本>-b<构建号>.ipa     # iPad
```

- 版本：`VERSION` 的 `0.0.x` 原样，不改分隔符、不补零。
- 构建号：CI 运行号，前缀固定小写 `b`，从 1 递增，永不复用。
- 分隔符只用半角连字符 `-`，不用下划线、空格、括号、中文顿号。

示例：

```
黄杨科技-0.0.3-b4.ipa
黄杨科技-HD-0.0.3-b4.ipa
```

## 3. 构建制品命名

```
黄杨科技-<版本>-b<构建号>-iphone
黄杨科技-HD-<版本>-b<构建号>-ipad
黄杨科技-发布清单-<版本>-b<构建号>
```

制品名与对应 ipa 文件名的前两段保持一致，只把 `-iphone` / `-ipad` 作为端标识补在最末。

## 4. 展示文案

版本页（更多 → 版本）与发布单里统一写「产品名 + 版本 + 构建」：

```
黄杨科技 0.0.3 · b4 · 7a4e89f
黄杨科技 HD 0.0.3 · b4 · 7a4e89f
```

提交号取 7 位，与 `git log --oneline` 一致。

## 5. 版本号口径

- `0.0.x` 表示内部自用版本，一次上线推进一位 patch，只由版本与发布管理员改。
- 同一版本号下可以重建多包（仅构建号变化），例如修 CI、改包名、补图标。
- 版本号与构建号都不写进文件名以外的位置（Info.plist 由构建脚本注入，不允许手改）。

## 6. 禁止事项

1. 手工重命名已发布的 ipa：一旦改名，`release-manifest.json` 的 sha256 与下载入口就对不上。
2. 在文件名里加日期、姓名、设备名、`.signed`、`final`、`v2` 之类的后缀或标记。
3. 用 `黄杨工作台`、`StocksLive`、`黄杨HD` 等旧名对外出包；旧名只保留在仓库与工程内部（target、scheme、bundle id 不动）。
4. 未经版本与发布管理员签发就推进 `VERSION`。

## 7. 变更流程

改规范本身要走同样一条链路：
`docs/RELEASE-NAMING.md` → `build-ipa.sh` → `tools/make_manifest.py` → `.github/workflows/ipa.yml` → 重建一次验证产物名，四者必须在同一个提交里改完。
